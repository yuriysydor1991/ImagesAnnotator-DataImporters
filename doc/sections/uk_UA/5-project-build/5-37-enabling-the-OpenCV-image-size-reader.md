## Вмикання читача розмірів зображень на OpenCV

Бібліотека не декодує жодного власного формату зображень. Саме тому існує `LibraryContext::set_image_sizer()`: анотація внутрішнього формату проекту - це прямокутник у пікселях зображення, над яким його намальовано, тож набір даних, який тих пікселів не зберігає, неможливо прочитати назад, не вимірявши картинку. Бібліотека просить свого споживача виконати те вимірювання тим набором засобів роботи із зображеннями, який той проект уже лінкує - завантажувачем GTKmm, Qt чи wxWidgets застосунку ImagesAnnotator, наприклад.

Споживач, якому нічого позичити, лишався ні з чим. Тому, коли збірка знаходить OpenCV, бібліотека несе і власний читач розмірів зображень, і такому споживачеві не потрібно надавати нічого.

Дві з трьох [розкладок наборів даних](/doc/sections/uk_UA/4-project-structure/4-10-the-read-dataset-layouts.md) без такого читача прочитати неможливо: YOLO v4, чиї рамки поділено на розмір зображення, і PyTorch Vision, чия анотація і є розміром самого обрізаного файлу. Розкладці простого тексту читач не потрібен, і вона заповнює розміри зображень лише тоді, коли він випадково є.

### Опція

```
cmake -S . -B build -DENABLE_OPENCV=ON
```

`ENABLE_OPENCV` за умовчанням `ON`, і `ON` означає *перевірити*, а не *вимагати*. Залежність необов'язкова в обидва боки:

| Ситуація | Наслідок |
| --- | --- |
| OpenCV встановлено | читач вкомпільовано, бібліотека лінкує `core` та `imgcodecs` |
| OpenCV не встановлено | конфігурація завершується успішно, друкує причину, бібліотека збирається без читача |
| `-DENABLE_OPENCV=OFF` | перевірку пропущено взагалі, наслідок той самий |

Ніщо з цього не провалює конфігурацію. Відсутність OpenCV означає лише, що імпорти і надалі просять читача у свого споживача.

Вкажи перевірці власний префікс через `-DOpenCV_DIR=<тека>`, коли встановлення не в типовому системному місці, і зміни перелік потрібних компонентів через `-DTEMPLATE_APP_OPENCV_COMPONENTS="core;imgcodecs"`.

### Який читач використає імпорт

Правило в один рядок: **наданий тобою читач завжди перемагає.**

1. Читач передано через `LibraryContext::set_image_sizer()` - використано саме той читач. Проект, який уже декодує зображення власним способом, продовжує робити рівно це, є в бібліотеки OpenCV чи немає.
1. Місце лишили порожнім, а бібліотека має читач на OpenCV - імпорт бере його, і налаштовувати не довелось нічого.
1. Місце лишили порожнім, і бібліотека не має читача - імпорт розкладки, якій він потрібен, одразу завершується невдачею із відповідним записом у журналі. Імпорт розкладки простого тексту працює далі й лише лишає розміри зображень своїх записів нулями.

Тож новий споживач може просто не чіпати це поле.

### Прямий запит

`LibraryFacade::create_image_sizer()` видає той самий читач або `nullptr` у збірці без OpenCV. Це і є спосіб дізнатись, чи має збірка читач:

```cpp
namespace iadi = ImagesAnnotatorDataImporters011;

auto ctx = iadi::LibraryFacade::create_yolo4_library_context();
ctx->set_import_path("/tmp/yolo-dataset");
ctx->set_db(db);

// Необов'язково. Якщо поле не чіпати, буде використано той самий читач.
ctx->set_image_sizer(iadi::LibraryFacade::create_image_sizer());

if (ctx->get_image_sizer() == nullptr) {
  // Ця збірка без OpenCV - надай власний читач або обери формат
  // імпорту, якому читач не потрібен.
}
```

### Що він робить

`read_image_size()` декодує файл за заданим шляхом і повідомляє його ширину та висоту:

- файл, який він не може декодувати, і файл, якого взагалі немає, обидва провалюють виклик, і це коштує лише того одного зображення, а не всього запуску імпорту;
- обидва вихідні параметри лишаються недоторканими у разі невдачі, тож той, хто викликає, ніколи не бачить половини вимірювання;
- уся картинка декодується заради двох чисел, бо C++ API OpenCV не має перевірки самого лише заголовка. Зменшені прапорці `IMREAD_` декодували б менше, але повідомляли б зменшений розмір, а рамка, масштабована за таким припущенням, є рамкою не на своєму місці.

Жоден тип OpenCV не з'являється у жодному встановлюваному заголовку. Читач доступний через абстрактний `IImageSizeFacility` так само, як будь-який наданий споживачем, тож **проекту-споживачу цієї бібліотеки не потрібен власний OpenCV**, навіть коли бібліотеку зібрано з ним.

### Тести

`UTEST_OpenCVImageSizer` покриває читач і конфігурується лише у збірці, яка знайшла OpenCV, оскільки кожен його випадок працює саме з ним. Збірку без OpenCV покриває `UTEST_LibFactory.create_image_sizer_matches_what_the_build_found`, який стверджує, що фабрика там не видає нічого. Набори тестів імпортерів керують і читачем, що повідомляє сталий розмір, і таким, що провалює кожен виклик, тож те, як імпорт поводиться з кожним із них, покрито у будь-якій конфігурації.
